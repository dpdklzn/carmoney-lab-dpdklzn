# Intent: правило «пробег авто не больше 400 000 км, иначе решение review»

ID задачи: `MILEAGE`. Собрано по ответам пользователя в интервью Grill Me.

## Замысел

Добавить в расчёт решения по заявке проверку пробега автомобиля: пробег не больше 400 000 км — заявка решается по LTV как раньше; пробег больше 400 000 км — решение `review` в пределах действующей валидации. Сочетание с отказом по LTV требует отдельного согласования. — ответ в интервью.

## Зачем

Направлять заявки с пробегом выше согласованного порога на ручное рассмотрение (`review`) вместо автоматического одобрения по низкому LTV. — ответ в интервью (исходная формулировка задачи).

## Constraints

- Порог 400 000 км — «не больше» включительно: ровно 400 000 км решается по LTV, правило срабатывает от 400 001 км. — ответ в интервью.
- При пробеге выше порога заявка, которая получила бы `approve` по LTV, должна получить `review`. — ответ в интервью (исходная задача: «иначе решение review»).
- Приоритет `reject` (LTV > 85) и `review` по пробегу — открытый вопрос, см. ниже. — ответ в интервью.
- Валидация пробега остаётся как есть: 0–500 000 км, пробег выше 500 000 — ошибка валидации, до расчёта решения не доходит. — ответ в интервью; код: backend/config/rules.php; код: backend/src/Domain/ApplicationValidator.php.
- Отсутствующее поле пробега и `null` — ошибка валидации, до расчёта решения не доходит. — ответ в интервью; код: backend/src/Domain/ApplicationValidator.php.
- Пустая строка пробега приводится к 0 и допускается — текущее поведение сохраняется в этой задаче. — ответ в интервью.
- Решение остаётся `approve` / `review` / `reject`; структура ответа API не меняется, причина `review` не добавляется. — ответ в интервью.
