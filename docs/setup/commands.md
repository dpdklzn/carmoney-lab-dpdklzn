# Команда requirements (2.4.1)

Файл команды: `.kilo/commands/requirements.md`. Она явно запускает рутину из `.kilo/skills/requirements/SKILL.md`, а не полагается на автоматический выбор скилла. Формат скилла не скопирован в команду: указан раздел «Формат результата» исходной инструкции.

## Пример вызова

После Reload Window в новой сессии Kilo code / MiniMax M3:

```text
/requirements LOAN-12 docs/sources/LOAN-12.md
```

Ожидается вывод в чат и `docs/spec/spec_LOAN-12.md` с четырьмя разделами пользовательской рутины. Неподтверждённые числа не придумываются, разногласия остаются вопросами, код и тесты не меняются. При отсутствии ID или материала команда запрашивает уточнение.

## Проверка вызова

После инструкции вызвать команду пользователь предоставил ответ и сообщил об изменённом файле `docs/spec/spec_LOAN-12.md`. Сохранённый файл проверен: есть разделы «Требования», «Границы», «Не-цели», «Открытые вопросы». Вопросы содержат владельцев и ссылки на фрагменты исходных материалов. Нумерации REQ/AC и реализации кода нет. Исходный результат не отредактирован помощником.

Отдельный блок раскрытия slash-команды и вызова `skill` пока не предоставлен. Совпадение формата и наличие файла подтверждают результат, но не доказывают загрузку команды и скилла инструментом. Нужно отдельно уточнить фактический вызов без повторного исполнения.

Для сравнения: ручной запуск с доступным requirements использовал разделы «Требования / Границы / Не-цели / Открытые вопросы» и путь `docs/spec/`; без скилла агент выбрал пятираздельный intent и `docs/intent/`. Качество фактических требований проверяется отдельно от совпадения формата.

## Сравнение результата с ручным прогоном

| Признак | Ручной запрос со скиллом (2.2.2) | Результат после команды |
|---|---|---|
| Формат и путь | Четыре пользовательских раздела, docs/spec/spec_LOAN-12.md | Сохранены те же разделы и путь |
| План реализации и REQ/AC | Не добавлены | Не добавлены |
| Источники | Ссылки на П-1…П-5 и фрагменты материалов | Ссылки на П-1…П-5, разделы и фрагменты материалов |
| Граница 7 лет | Ложное противоречие между «старше 7» и «до 7 включительно» | Ошибка повторилась: «старше 7» неверно включает ровно 7 лет |
| Граница 20 лет | Непроверенное сомнение об off-by-one | Недоказанное противоречие повторилось: max_age: 20 само по себе не противоречит «старше 20» |

Команда воспроизводит пользовательский формат ручного прогона, но не обеспечивает корректность анализа источников. В результате также есть утверждение, что будущий год проходит текущую валидацию, без подтверждённого чтения кода; это нельзя считать проверенным поведением сервиса. Упоминания двух отдельных тестов в разделе границ выходят за чистую переформулировку требований, хотя новой тестовой реализации не создано.

Итог: файл результата и соблюдение формата подтверждены; точный вызов команды/скилла остаётся к подтверждению, замечания к качеству сохранены для следующих проверок. Ответ не принимается как согласованная новая бизнес-спецификация LOAN-12.
