# E2E-проверка: пробег 400001 км

Проверка через Playwright (Chromium) против работающего сервиса `http://localhost:8080`.
В ходе браузерного прогона код и настройки не менялись. До прогона в конфиг проекта добавлен Playwright MCP.

## Шаги

1. `playwright_browser_navigate http://localhost:8080/` — страница загружена, заголовок: «Предварительная оценка заявки на заём под ПТС».
2. Зафиксированы исходные значения формы по умолчанию.
3. Поле «Пробег, км» заменено на `400001` через `fill`.
4. Нажата кнопка «Отправить заявку».
5. Сделан полностраничный скриншот → `docs/setup/e2e_mileage_400001.png`.

## Входные значения формы

| Поле | Значение |
|---|---|
| Идентификатор клиента | `CL-0025` (по умолчанию) |
| VIN | `XTA21099998765432` (по умолчанию) |
| Год выпуска | `2019` (по умолчанию) |
| **Пробег, км** | **`400001`** (изменено) |
| Оценочная стоимость, ₽ | `900000` (по умолчанию, как в задании) |
| Запрошенная сумма, ₽ | `450000` (по умолчанию, как в задании) |
| Срок, месяцев | `24` (по умолчанию) |

## Текст блока «Решение» (дословно из DOM)

- Решение: **`review`**
- LTV: **`50 %`**
- Возраст авто: **`7 лет`**
- Одобренный лимит: **`0 ₽`**
- Номер заявки: **`25`**

Заголовок секции: «Решение». Текстового пояснения причины (например, «слишком большой пробег», «превышен лимит», «высокий LTV») на странице нет.

При визуальной проверке скриншота решение отображается как **`REVIEW`** (верхний регистр); приведённое выше `review` — текст DOM по отчёту агента. Остальные значения совпадают со скриншотом: `50 %`, `7 лет`, `0 ₽`, `25`. При пробеге `400001` и LTV `50 %` результат соответствует правилу перевода approve в review. Расхождения в решении с кодом не обнаружено.

## Объясняет ли интерфейс причину решения

**Нет.** Интерфейс показывает только факт решения (`review`) и сопутствующие метрики (LTV, возраст, лимит, номер заявки). Пользователь видит, что решение — `review` и одобренный лимит 0 ₽, но явного текстового объяснения причины (в т.ч. про пробег 400001) интерфейс не выводит.
