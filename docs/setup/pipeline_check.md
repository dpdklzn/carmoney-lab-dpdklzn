Две новые сессии Kilo code / MiniMax M3. В исходных просьбах инструменты не назывались. Фактические вызовы ниже предоставлены пользователем из ответов агента на просьбу перечислить предыдущие действия без новых вызовов.

| Просьба | Что позвал | Верно ли |
|---|---|---|
| «Проверь, что заявка с пробегом 400001 действительно уходит в review, и покажи, что при этом видит пользователь.» | Shell/curl, Grep/Read, Playwright: навигация, снимки DOM, заполнение формы, отправка. ast-index не вызывал. | Браузер выбран верно: результат проверен в форме. Индекс не использован; попытка скриншота завершилась ошибкой. |
| «Скажи, где в коде задаётся порог пробега и какое значение там стоит сейчас.» | Только Read `backend/config/rules.php`; без Shell, ast-index и Playwright. | Верно для выбора браузера: ответ получен из конфига, браузер не запускался. Инструкция поиска через индекс не применялась. |

## Первая сессия

Shell: `ls /Users/admin/carmoney-lab`; проверка HTTP-статуса `/health` через curl; POST `/applications` (ошибка 404), затем исправленный POST `/api/applications` с пробегом 400001 и сравнение двух заявок с пробегом 400000/400001. Полные JSON-тела shell-команд в предоставленном списке опущены, здесь не восстанавливаются как выполненные команды.

Поиск и чтение: Grep `mileage|400001|review` в `backend/`; Read `backend/config/rules.php`; Read каталога `frontend/`; Grep `review|result|decision|status` в `frontend/app.js`; Read `backend/src/Domain/ApplicationValidator.php`; Grep маршрутов в `backend/`.

Вызовы Playwright по предоставленному списку:

1. `playwright_browser_navigate` — `http://localhost:8080/`.
2. `playwright_browser_snapshot` — до заполнения.
3. `playwright_browser_fill_form` — шесть полей.
4. `playwright_browser_click` — «Отправить заявку».
5. `playwright_browser_snapshot` — после отправки.
6. `playwright_browser_take_screenshot` — ошибка: вкладка уже закрылась.
7. `playwright_browser_close`.

По ответу агента, год 2020, стоимость 1000000, сумма 200000 дали LTV 20%: при пробеге 400000 — approve и лимит 200000, при 400001 — review и лимит 0. Текст результата браузерной проверки по предоставленному ответу: `review`, `20 %`, `6 лет`, `0 ₽`, номер заявки `37`. Новый скриншот этого запуска не получен; успешный скриншот из 2.1.3 — отдельное свидетельство, не подмена отсутствующего снимка.

## Вторая сессия

Единственный вызов: Read `backend/config/rules.php`. Ответ назвал `max_mileage_km = 500000` как предел валидации и `review_max_mileage_km = 400000` как порог решения. Агент сообщил, что ast-index, Shell и браузер не вызывал.

## Вывод

Браузер используется для проверки пользовательского результата и не используется для вопроса о конфиге. Самостоятельный выбор браузера соответствует обеим просьбам. Автоматического использования ast-index не наблюдалось. Численные затраты недоступны через корпоративный доступ; они отмечены в `docs/metrics/tokens_d2.md` без выдуманных значений.
