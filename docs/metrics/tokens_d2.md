# Сравнение поиска без индекса и с ast-index

Задание 2.1.1, трек «Аналитик». Модель: MiniMax M3; агент: ask. Для обоих запусков используются новые сессии и одинаковый промпт:

```text
Какие пороги и правила про пробег реально зашиты в коде и где они лежат? Отвечай по коду этого репозитория, по строке на место — файл и функция. Ничего не выдумывай: чего нет — пиши «нет».
```

## Замеры

| Запуск | Input tokens | Output tokens | Стоимость, $ | Агент звал ast-index |
|---|---|---|---|---|
| без индекса | недоступно | недоступно | недоступно | нет: запуск до установки инструмента |
| ast-index | недоступно | недоступно | недоступно | нет: подтверждено ответом агента о вызовах |

Пользователь работает через корпоративный токен Kilo и не имеет аккаунта OpenRouter. Метрики Activity недоступны; значения не оценивались и не заменялись нулями. Для завершения количественного сравнения нужны данные корпоративного провайдера или согласованный организаторами источник статистики. Если одна сессия выполняет несколько запросов к модели, учитывается их суммарный расход; по возможности отдельно фиксируются кешированные токены.

## Первый ответ и подготовка индекса

В первом ответе агент нашёл валидационный предел 500000 км и порог решения 400000 км. Указаны `ApplicationValidator::validate()`, `DecisionEngine::decide()` и передача порога в `AppFactory::create()`. Уточнение при сверке: ровно 400000 км не гарантирует approve — решение остаётся по LTV. Лента инструментов первого запуска не предоставлена.

Установлен ast-index 3.56.0 через Homebrew. Индекс построен командой:

```bash
ast-index rebuild --exclude '*.env*' --exclude 'vendor/**' --exclude '.kilo/worktrees/**'
```

`ast-index stats`: PHP-проект, 25 файлов, 186 символов, 934 ссылки. Проверочный вызов `ast-index class DecisionEngine` нашёл `backend/src/Domain/DecisionEngine.php:18`. Эти команды выполнил помощник для настройки; они не считаются вызовами агента Kilo в замере «после».

В AGENTS.md добавлено правило поиска через индекс. База индекса хранится в локальном кэше вне репозитория.

## Второй запуск и вывод

В новой сессии Kilo ask / MiniMax M3 получен ответ с обоими порогами и правилами валидации и решения. Скриншот ленты показывает `ls` и Grep. На дополнительный вопрос о фактически выполненных действиях агент перечислил:

1. `ls /Users/admin/carmoney-lab` — обзор корня.
2. Grep с регистронезависимым шаблоном `пробег|mileage|odometer` по репозиторию.
3. Read `backend/config/rules.php`.
4. Read `backend/src/Domain/ApplicationValidator.php`.
5. Glob `backend/src/**/*.php`.
6. Read `backend/src/Domain/DecisionEngine.php`.
7. Read `backend/src/Domain/AssessmentService.php`.

Агент явно сообщил, что `ast-index` не вызывал. Точная командная строка Grep не предоставлена; перечислены инструмент и шаблон, а не выдуманная shell-команда. В ленте виден счётчик 16500, но его смысл не подтверждён, поэтому он не записан как input/output tokens.

Вывод: после установки индекса и добавления инструкции агент продолжил использовать текстовый поиск и чтение файлов. Использование структурного индекса в этом запуске не подтверждено — по ответу агента его не было. Экономию токенов и стоимости оценить нельзя без метрик провайдера. Практическое наблюдение сохранено, но количественная часть задания остаётся незавершённой.

## Дополнительная диагностика доступа

По явному запросу использовать CLI агент в ask смог выполнить `which ast-index` (путь `/opt/homebrew/bin/ast-index`), но запуск `ast-index --help` был отклонён политикой сессии. Скриншот также показывает блокировку составной команды с конвейером. По ответу агента, простые команды ast-index тоже запрещены эффективными правами этой сессии. Поэтому одно правило в AGENTS.md не обеспечивает доступность инструмента.

После рекомендации проверить инструмент в отдельной сессии code пользователь предоставил успешный результат команды:

```bash
ast-index search mileage
```

Возвращены 6 символов: `decide` (`backend/src/Domain/DecisionEngine.php:36`), `NUMERIC_FIELDS` (`frontend/app.js:8`), `mileageRules` (`tests/Unit/DecisionEngineTest.php:50`), `testDecidesByLtv` (`tests/Unit/DecisionEngineTest.php:25`), `testAppliesMileageRule` (`tests/Unit/DecisionEngineTest.php:44`), `payload` (`tests/Unit/AssessmentServiceTest.php:37`). Также найдены 46 текстовых совпадений, показаны первые 20.

Это подтверждает успешный вызов CLI в дополнительной попытке. В исходной строке замера ask остаётся «нет»: явная команда и другой режим не являются повторением исходных условий. Input/output и стоимость дополнительного запуска также не предоставлены. Вывод всех оставшихся совпадений для подтверждения вызова не нужен.
