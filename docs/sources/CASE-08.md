# CASE-08 · Оценка залога по VIN

> Учебная синтетическая версия, заполненная 2026-10-13 по прямому поручению постановщика «Придумай все это сам». Все параметры, примеры и фрагменты ниже придуманы для курса; это не реальные кредитные правила, регламент или статистика. Значения из прежней заготовки не выдаются за ранее утверждённые источники.

## 1. Процесс

По VIN заявки сервис получает из учебного справочника базовую цену, год выпуска, пробег и комплектацию. На их основе рассчитывает залоговую стоимость, сверяет характеристики с заявкой и определяет решение. Стоимость из заявки не заменяет отсутствующую оценку справочника.

Участники: сервис оценки, внешний синтетический мок, андеррайтер. Справочник хранит только синтетические VIN, не связанные с владельцами.

## 2. Правила и источники параметров

### П-1. Оценка

Базовая цена B — положительное целое число рублей. Пробег и возраст берутся из справочника, а не из заявки. Возраст A = текущий календарный год сервиса − год выпуска справочника, без учёта месяца. Для примеров ниже год зафиксирован как 2026; в рабочем коде год не фиксируется.

| Пробег справочника, км | Скидка dM |
|---|---|
| 0 ≤ M ≤ 100000 | 0% |
| 100000 < M ≤ 200000 | 5% |
| 200000 < M ≤ 300000 | 10% |
| 300000 < M ≤ 500000 | 15% |

| Возраст справочника, полных лет | Скидка dA |
|---|---|
| 0 ≤ A ≤ 3 | 0% |
| 3 < A ≤ 7 | 5% |
| 7 < A ≤ 12 | 10% |
| 12 < A ≤ 20 | 20% |

V = round_half_up(B × (1 − dM − dA)) до целого рубля. dM/dA в формуле — доли, например 5% = 0.05. Сначала складываются скидки от одной базовой цены, затем один раз округляется итог; промежуточного округления и перемножения скидок нет.

Источник таблиц: SIM-REG-CASE08, решение DEC-08-01. Формула и округление: ответ интервью и DEC-08-01. Максимальная суммарная скидка 35% — производное от 15% + 20%, а не дополнительный бизнес-порог.

### П-2. Сверка

Год и комплектация должны совпадать точно; комплектация — строковый идентификатор без нечёткой нормализации. Пробег — неотрицательное целое число км. Delta = abs(M_заявки − M_справочника); Delta ≤ 10000 км допустимо. Delta > 10000 либо несовпадение года/комплектации переводит только approve в review; review и reject по LTV сохраняются. При нескольких несовпадениях возвращаются все причины в порядке: пробег, год, комплектация.

Источник: интервью, SIM-REG-CASE08, DEC-08-02. 10000 км — новое синтетическое значение, выбранное по поручению постановщика; не путать с валидационным пределом 500000 км.

Точные причины в этом учебном API: «Расхождение пробега превышает допустимый порог», «Год выпуска не совпадает со справочником», «Комплектация не совпадает со справочником».

### П-3. Нет VIN и неполные данные

Ответ справочника «не найдено» → review, V = null, LTV = null, причина «Нет данных по VIN в справочнике». Никакой приблизительной оценки, нулевого заменителя или fallback на стоимость заявки.

Неполный/некорректный ответ, ошибка транспорта или сервиса → review, V = null, LTV = null, причина «Данные справочника неполные или некорректные». Некорректны: отсутствующее обязательное поле, пустая комплектация, нецелые/отрицательные пробег или базовая цена, B ≤ 0, год в будущем, возраст >20 или пробег >500000. Превращать отсутствующий пробег справочника в 0 запрещено. Если итог V ≤0 или расчёт не даёт конечного значения, действует то же поведение.

Источник отсутствия VIN: исходный П-3 и интервью. Дополненные случаи: синтетическое решение DEC-08-03.

### П-4. Таймаут

На один запрос справочника даётся 1500 мс. Ответ принимается только если запрос полностью завершён за время t <1500 мс; t ≥1500 — таймаут. Результат: review, V = null, LTV = null, причина «Справочник не ответил вовремя». Поздний ответ не меняет уже выданное решение. Автоматических повторов нет.

Источник: интервью, синтетическое решение DEC-08-04. Контроль времени монотонный; тесты используют управляемые часы/заглушку, не реальное ожидание сетевых задержек.

### П-5. LTV и приоритет

При V >0: LTV = round_half_up(запрошенная сумма / V ×100) до двух знаков, как в существующем расчёте. Решение по LTV сохраняет фактическое поведение командного кода: <60% — approve; 60%..85% включительно — review; >85% — reject. Эти пороги не изменяются эпиком. Комментарий «≤60 — approve» не является источником фактического сравнения.

Reject по рассчитанному LTV сохраняет приоритет над review по сверке. При невозможности оценки LTV не вычисляется; применяется review по П-3/П-4. Существующий одобренный лимит: запрошенная сумма при approve, иначе 0.

Источник: интервью; backend/config/rules.php, блок ltv; backend/src/Domain/DecisionEngine.php::decide(); LtvCalculator::calculate(); AssessmentService::assess(). Числа 60/85/0/2 знака — существующая логика, не синтетическая замена конфигурации.

### П-6. API и сохранение

Существующие POST /api/ltv и POST /api/applications поддерживают оценку CASE-08. Первое не сохраняет заявку, второе сохраняет. В валидную заявку добавляется обязательная непустая строка equipment для сверки; VIN/year/mileage/market_value/requested_amount/term_months сохраняют действующую валидацию. market_value заявки не становится знаменателем LTV. Дополнительные требования к валидации equipment: отсутствие/null/пустая строка/нестроковое значение → ошибка по equipment.

Оба ответа содержат collateral_value (целые рубли или null), ltv (число или null), decision, approved_limit, assessment_reasons (массив строк). Остальные существующие поля сохранены; у создания заявки есть id. При совпадении данных и отсутствии проблем массив причин CASE-08 пуст; причина по LTV сама по себе не добавляется этим кейсом. Причины расхождений возвращаются и при reject для диагностики, не меняя решение. При ошибке справочника массив содержит соответствующую причину П-3/П-4.

Успешная оценка или review из-за зависимости — HTTP 200 для /api/ltv, HTTP 201 для созданной /api/applications. Ошибка входной заявки — HTTP 422, запрос справочника не выполняется. Отсутствующая оценка/LTV должны сохраняться как null, а не фиктивные числа; для этого разрешено изменить схему хранения и добавить миграцию. Ранее сохранённые решения и записи не теряются.

Источник: синтетическое решение DEC-08-05 и интервью о причинах review; статусы 200/201/422 — действующий HTTP-контракт ApplicationController. Пустая equipment и null выходной оценки — новый контракт CASE-08, не утверждение о возможностях текущего сервиса.

## 3. Синтетические примеры

| E-01 / XTA21099998765001 | 2023 / 100000 | 2023 / 100000 | 500000 | 1000000 | 50.00 | approve |
| E-02 / XTA21099998765002 | 2023 / 100001 | 2023 / 100001 | 500000 | 950000 | 52.63 | approve |

## 4. Граничные и неизвестные данные

- Пробег скидки: 99999/100000/100001, 199999/200000/200001, 299999/300000/300001; 0/500000 допустимы, -1/500001 в справочнике некорректны.
- Возраст скидки: 2/3/4, 6/7/8, 11/12/13; 0/20 допустимы, -1/21 некорректны.
- Delta: 9999/10000/10001, оба направления расхождения. При равенстве порогу review не добавляется.
- Таймаут: 1499 мс — ответ допустим; 1500/1501 — review, без оценки.
- Нет VIN, null/пустой/неполный ответ справочника, B =0, пустая комплектация, год в будущем.
- LTV 59.99/60/85/85.01; reject не смягчается при расхождении.
- Округление: B =100001 ₽, dM =5%, dA =5% → V =90001 ₽ (не 90000); формула аддитивная даёт 90%, а перемножение 95% ×95% дало бы 90.25%.
- Дополнительный тест половины рубля: B =100005 ₽ при тех же скидках даёт 90004.5 ₽ до округления и V =90005 ₽ после него.
- Для сверки в обоих направлениях M справочника =150000, M заявки =140001/140000/139999 либо 159999/160000/160001: абсолютная разница 9999/10000/10001 км.
- Входная заявка с equipment отсутствующим/null/пустым/нестроковым значением →422; неизвестная, но непустая комплектация →расхождение при сравнении со справочником.

Значения «граница ±1» — производные от П-1/П-2/П-4 и минимальной единицы входа (км/год/мс), а не новые пороги.

## 5. Фрагменты-источники (все придуманы)

### SIM-REG-CASE08 · учебный регламент · 2026-10-13

Таблицы скидок — П-1. Скидки складываются от общей базовой цены, итог округляется один раз. Допустимое расхождение пробега 10000 км включительно. При расхождении approve переводится в review, reject сохраняется. Нет данных — не выдавать оценку.

### SIM-TICKET-CASE08 · учебный тикет · 2026-10-13

Альтернативное предложение для упражнения: применять скидки последовательно (перемножать), допускать расхождение до 20000 км; таймаут возвращать как HTTP 504. Это намеренно конфликтующие предложения, не обязательные требования.

### SIM-DATA-CASE08 · учебная мини-выгрузка · 2026-10-13

| Запись | Пробег заявки / справочника | Решение в выдуманной старой системе |
|---|---|---|
| D-01 | 110000 / 100000 | approve |
| D-02 | 110001 / 100000 | approve |

Это синтетические примеры нежелательного поведения, а не доказательство правильного правила.

## 6. Решения по расхождениям

- DEC-08-01: выбран аддитивный расчёт и таблицы П-1, а не последовательные скидки из SIM-TICKET.
- DEC-08-02: выбран порог 10000 км включительно, а не 20000 и не историческое поведение SIM-DATA.
- DEC-08-03: отсутствие/неполнота данных →review без V/LTV; приблизительная подстановка запрещена.
- DEC-08-04: выбран таймаут 1500 мс и review без повтора, а не HTTP 504 для валидной заявки.
- DEC-08-05: принят новый контракт П-6, включая equipment, причины и nullable-оценку.

Источник решений DEC: прямое поручение пользователя 2026-10-13 самостоятельно заполнить синтетические материалы. Качественная основа — ранее предоставленные ответы интервью. Реальные согласования риск-менеджмента этим документом не имитируются.
